# QuantNative 2.6.0-review

基于 2.4.0-review 的 Windows 本地候选版。2.5.0 修了午休净值、浮窗显隐、海外指数关联；2.5.1/2.5.2 把盘中涨跌接到实时数据上并纠正了口径错误；**2.6.0 把盘中估值从「关联板块等权」换成「前十大重仓加权」—— 与养基宝同一套算法，涨跌方向不会再反着走。**

单文件绿色版：`QuantNative.exe` 复制到任意目录即可运行，同目录放一个空的 `portable.dat` 就进入便携模式（数据写入同目录 `data\`，不碰注册表和 `%AppData%`）。

## 零、2.6.0：盘中估值改用前十大重仓加权

现象：养基宝上 017811（东方人工智能主题混合C）是**负收益**，浮窗却是**正的**。

根因：2.5.x 用「关联板块等权」当估值。板块只是主题代理，和基金真实持仓可以反着走。2026-10-20 上午实测：

| 口径 | 数值 |
| --- | --- |
| 关联板块：半导体材料 +2.76%、半导体设备 +0.92% → 等权 | **+1.84%**（浮窗显示的就是这个） |
| 前十大重仓：中科飞测 −3.11%、拓荆 −1.80%、华海清科 −1.19%… 按占净值比例加权 | **−0.39%**（与养基宝一致） |

修法：新增 `Data/HoldingsEstimator.cs`，按养基宝 / 天天基金的算法算估值：

```
估算涨跌 = Σ(前十大持仓的「占净值比例 %」× 该股当日涨跌 %) / 100
```

- 未披露部分（现金 + 非重仓股）按持平处理，所以不会放大波动；
- 重仓合计权重 < 5% 就不估（信息不足宁可不显示）；
- 重仓名单 6 小时缓存、失败 5 分钟重试；个股行情用主数据源（腾讯/新浪）批量取，4 秒 TTL，**不走被区域网络限制的东财 push2**；
- 拿不到重仓（QDII、季报缺失、接口不通）才退回关联板块等权，口径文字会写明是「重仓股 10 只 · 覆盖 83%」还是「板块 2 个等权」；
- 优先级仍是：**今日正式净值 > 重仓股估值 > 板块等权 > 只给上一净值（涨跌幅留空）**。

### 顺带说明：QDII 的净值为什么看着「没更新」

021000（南方纳斯达克100指数发起）在 2026-10-20 上午显示净值日期 10-16，这是**对的** —— 我核了天天基金接口：

```
021000  最新净值 2.2475  净值日期 2026-10-16  （10-19 的净值还没公布）
017811  最新净值 2.7501  净值日期 2026-10-19  （A 股基金 T 日净值当晚公布）
```

QDII 投的是海外市场，净值要按当地收盘价折算，披露节奏是 **T+1～T+2**（10-19 的净值通常 10-20 晚间才出）。这期间要看「10-19 美股那一夜」的涨跌，只能看**跟踪指数的估值**：纳斯达克100 当日 +1.11%，浮窗显示的就是这个数。2.6.0 在口径行里补了「（QDII 净值 T+1 公布）」的说明，避免把「净值日期停在 10-16」误读成程序没更新。

## 零（2.5.2）、不再把「上一交易日的涨跌幅」当成今天的

现象：把 017811 的关联板块改成 半导体材料 / 半导体设备 之后，界面上仍显示 `-0.08%` —— 那是这只基金**上一交易日净值**的涨跌幅，不是今天的，更不是板块的。

根因：`Describe` 的第三档（既没有今日净值、也没有板块行情）沿用了「上一净值 + 它自带的涨跌幅」。板块行情没到、或东财 push2 被网络挡住时，就一路落到这里，于是把昨天的数字摆在了「今天」的位置。

修法：

- 新增 `IsTodayNav`：只有**净值日期 = 今天**才算今日净值，它后面的日涨跌才是真的当日涨跌；
- `Describe` 三档改为：**今日净值 > 板块等权估值 > 只给上一净值（涨跌幅强制留空）**；
- 浮窗里，基金只要有板块关联就**不会**再显示基金自己的净值涨跌幅：有板块行情就合成一行估值，没行情就逐条列板块并标「待更新」；
- 自选表 / 面板页在第三档只把上一净值显示成弱色，涨跌与涨跌幅两列留 `—`。

以 2026-10-19 午休的实测为例：017811 最新净值 2.9203（10-16，官方日涨跌 −0.08%，正是之前被误当成今日的那个数），关联的 半导体材料 −1.00%、半导体设备 −3.35%，等权 −2.175% → 现在显示 `2.8568* / −0.064 / −2.18%`。

## 零（2.5.1）、基金涨跌跟着关联板块实时走

旧行为：交易时段场外基金的涨跌列固定是 `—`，只在浮窗/详情里把关联板块逐条列出来 —— 用户看到的是「基金涨跌根本不跟板块走」。

新行为：把关联板块的涨跌幅**等权平均**，得到当日估算，四个界面统一从这里取值（`AppHost.EstimateFund` + `FundPresentation.Describe`）：

| 位置 | 盘中 / 午休（有板块行情时） |
| --- | --- |
| 自选表 | 现价 = 估值净值（`3.2185*`）、涨跌 = 估值−上一净值、涨跌幅 = 等权估算 |
| 面板自选页 | 现价 = 估值净值（`*`）、涨跌幅 = 等权估算 |
| 浮窗 | 基金合成**一行**：估值 + 等权涨跌幅（以前是一只基金铺 3 行板块） |
| 详情 | 主数值 = 估值净值 + 涨跌幅，口径行「估值 11:44 · 关联板块 2 个等权 · 上一净值 3.2037（10-16）」 |

三档口径（`FundDisplay`，2.5.2 定稿）：

1. **当天正式净值已公布**（净值日期 = 今天）→ 显示正式净值与官方日涨跌，估值让位；
2. **否则有板块行情** → 估值（价格带 `*`），午休也照常跟板块走；
3. **两者都没有** → 只显示上一净值（弱色），**涨跌幅留空**（绝不复用上一交易日的数字）。

规则与边界：
- 只统计**新鲜**行情：A 股板块要求当日且 2 分钟内收到过，海外指数放宽到最近 5 天；过期板块不参与平均，只在口径里注明「N 个待更新」。
- 没有任何可用板块行情时不会瞎估，也不会拿旧数字充数。
- 估值公式 `上一净值 ×(1 + 等权涨跌幅)`，`*` 与 tooltip 都写明「不是基金公司净值」。
- 板块报价每 5 秒（海外指数 20 秒）刷新一次，`QuotesUpdated` 一到就重算，所以数字是滚动的。

## 零（2.5.0）、修了什么

### 1. 午休不再「没有数据」，一律显示最新值

场外基金的口径是「交易时段看关联板块、净值公布后看净值」。但午休（11:30–13:00）盘面完全不动，板块行情也停在上午收盘价，旧逻辑仍然把基金净值藏起来 —— 结果详情、自选、浮窗一起变成`—`，看起来像这只基金没数据。

- `FundPresentation.UseNav` 增加午休分支：11:30–13:00 直接显示**已公布的最新净值**，口径行写明「净值 2026-10-16」，不会冒充当日净值。
- 盘中（板块模式）也不再只写一个 `—`：主数值改为**上一净值**（弱色，明确不是当日值），下面一行写「上一净值 2026-10-16 · 盘中参考关联板块」。
- 自选表、面板自选页同步调整：现价列显示上一净值（弱色），净值日期跟在「关联板块 / 净值日期」列里。
- 右侧摘要区在板块模式下多一行「上一净值 3.216（10-16）」。

### 2. 浮窗显示/隐藏按钮不再失灵

查到四个独立原因，逐个修：

1. **句柄从没创建**：`ShowBySchedule` 里有 `if (!IsHandleCreated) return;`。如果在隐藏时段启动（比如下午 4 点、时段设成 09:30–15:05），浮窗一次都没 `Show()` 过、句柄始终不存在，之后点「显示浮窗」永远走进这个提前返回 —— 按钮彻底失效。现在先建句柄再显示。
2. **调度器把浮窗拉回来**：面板（管理自选/设置）原来用 `bar.Hide()` 收浮窗，调度器每秒核对一次「该显示却没显示」，一秒内又把浮窗拉回面板上面。新增 `HoldForPanel()` / `ReleaseFromPanel()`，面板接管期间调度器不再插手。
3. **启动时忽略上次的隐藏状态**：昨天关掉浮窗、今天开机，调度器看到「该显示却没显示」立刻把它拉出来。新增 `StartHiddenByIntent()`，按落盘的 `ticker_visible` 恢复，并一直保持到下一个时段边界。
4. **窗口跑到屏幕外 / 被置顶窗盖住**：现在每次显示都重新贴边（`EnsureOnScreen`）、重新置顶、重新推一帧分层位图，显示后还会复查 `IsWindowVisible` 并补一次修正。

每次显隐都会写一行日志（`浮窗 → 显示 / 隐藏`），以后再看日志就能确定是「没点」还是「点了没生效」。

### 3. 海外指数基金可以自动关联了

`南方纳斯达克100指数发起(QDII)I 021000` 这类基金的关联一直失败：它跟踪的是海外指数，A 股板块目录里根本没有「纳斯达克」，取重仓股也拿不到 A 股行业（持仓是美股），两路信号全空。

- 新增 `Core/IndexBoards.cs`：9 个常用海外指数登记成**伪板块**，代码 `ix` + 东财 secid（`ix100.NDX`、`ix124.HSTECH`…），名称与 A 股板块同构，直接复用现有的名称匹配打分。
- 行情走 push2 `ulist.np`（secid 原样传，没有 A 股板块的 `90.` 前缀），海外指数单独 20 秒 TTL；海外指数跨隔夜/周末仍算「最新一期」，不会再被判成「数据待更新」。
- 主题别名补了纳斯达克/纳指/标普/道琼斯/恒生/恒生科技/日经/德国 DAX/法国 CAC40/富时等写法。
- 板块目录快照重新生成：**504 → 1011 项**（2026-10-19 的行业 + 概念全量），落盘在 `Data/BoardCatalogSnapshot.cs`。
- 顺带把板块接口失败的日志做了限频（同一板块 1 分钟一条）：旧版接口整段不可达时日志一分钟能写几百行、单文件冲到 2 MB。

## 一、界面设计（对齐养基宝视觉语言）

- 默认配色改为**养基宝风格双主题**：浅色 `yangjibao`（灰底 + 纯白卡片 + 品牌橙红强调）与深色 `yangjibao-dark`。共 6 套主题在内置菜单里可切换。
- 引入**三级表面层次**：页面底色 `Bg`（浅灰）→ 卡片 `Card`（纯白圆角）→ 分隔 `Divider`。行情表、详情面板、浮窗底图都改成卡片承载，不再是一整块平铺的表格。
- 顶栏重绘：品牌圆点 + 产品名 + 副标题 + **实时交易时段胶囊**（开盘/午休/收盘，配色随状态变化）。
- **显示层级重建**：`现价`、`涨跌幅` 两列改用强调样式（加粗、放大、等宽数字字体），自选列表里涨跌幅直接画成**带底色的胶囊**，选中行左侧带强调色竖条，一眼能分出主次。
- 大盘指数条从「一行文字」改为**等宽圆角卡片**：名称（小字）→ 指数值（大字，涨红跌绿）→ 涨跌 + 百分比（等宽字体，三行固定结构）。卡片宽度按文本实测自适应，最小 118 px，空间不够时整体收缩而不是重叠换行。

## 二、浮窗定时隐藏 / 每日显示时段

- 设置页新增「显示时段」：勾选启用后，用两个时间选择器设定每天的**开始显示时间**与**结束显示时间**。
- 判定规则（`TickerSchedule`，纯函数、可单测）：
  - 起 < 止 —— 常规窗口，如 `09:15 – 23:30`；
  - 起 > 止 —— **跨零点窗口**，如 `22:00 – 02:00`，自动拆成两段判定；
  - 起 == 止 —— 视为**全天显示**（避免两端拖成同一值后浮窗彻底消失）。
- 窗口外浮窗自动隐藏，到点自动回来；内部按「距下一次切换的秒数」定时唤醒，不每秒空转。设置页实时显示一行说明，如「22:00 – 次日 02:00 显示（跨零点）」。

## 三、字体与数值

- 浮窗字体改为**读取本机已安装字体族**（`Theme.InstalledFamilies()`）下拉选择，界面字体与数字字体可分别设置；选到不存在的字体时安全回退到真实族，不会崩。
- 浮窗字号可调，字号变化会同步重算行高与可见行数。
- **所有数值统一 3 位小数**（指数、现价、净值、涨跌幅百分比），浮窗、表格、详情、大盘全部走同一格式化入口。
- 修掉一个隐蔽的 GDI+ 坑：`DrawString` 在**矩形高度小于字体的行高**时会**静默不画**（不报错、不裁剪，直接什么都没有）。新增 `Theme.TextRow` 把矩形撑到至少 `font.Height + padding` 并垂直居中，大盘成交额这类大号数字才真正显示出来。

## 四、数据更新

- 新增**刷新档位**（`RefreshProfile`），可在设置页或右键菜单切换，当前档位显示在主界面状态栏：
  - `极速（1 秒）` / `均衡（2 秒）` / `省流（5 秒）`，另有默认 `Fast`。
  - 交易时段按档位取间隔，非交易时段自动放宽；探测间隔也随档位调整（省流/均衡为 2 秒，其余 1 秒）。
- 新增**「立即刷新」**按钮（主界面 + 浮窗菜单 + 托盘菜单），一键强制拉取当前数据，不用等下一个周期。
- 修复**大盘数据错位**：根因之一是数据源返回顺序不稳定，直接按返回顺序摆放会导致指数串位、张冠李戴。新增 `QuoteHub.NormalizeIndices`，按 `Symbols.IndexRank` 固定排名排序（上证指数 → 深证成指 → 创业板指 → 科创50 → 中证500），缺失名称回填前缀。另一个根因是概览面板原先用硬编码像素偏移，已改为按文本实测宽度布局。
- 基金正式净值改用轻量净值明细接口并行获取，历史曲线才读完整历史文件；腾讯与新浪行情互相补缺，东方财富股票批量报价作为第三路备用；板块批量报价带 5 秒缓存，到达即刷新界面。交易期间不因价格暂时不变而退避到 30 秒。

## 五、自选基金自动关联

- 关联策略对齐主流基金 App 的做法，按**证据强弱分两级**：
  1. **持仓行业优先** —— 先取基金前十大重仓所属行业，用行业去板块目录里找明确匹配；
  2. **名称兜底** —— 持仓拿不到时，才用基金名称去匹配。
- 「一键关联全部基金」入口放在设置页、浮窗右键菜单与托盘菜单，自动匹配不会覆盖手动保存的结果。
- 关联窗口补上「自动推荐」重算、搜索、移除、排序，并收紧文案说明推荐依据。
- 明细里新增 `AppHost.SuggestBoardsAsync(基金代码, 基金名称)`，把「取持仓行业 → 匹配板块」两步串成一次调用。

> 说明：搜索同时使用实时提示接口、行业/概念目录和 2026-10-19 的 1011 项板块离线快照（行业 + 概念，另加 9 个海外指数伪板块）。**这些是公开数据推荐，不是养基宝原始映射；没有养基宝可读取的关联表或授权接口时，无法宣称两者完全一致。**

## 六、浮窗尺寸自由拖拽

- 浮窗去掉尺寸限制，宽度 240–720 px、高度可自由拖拽；拖动后的宽高会**持久化**，下次启动按上次尺寸恢复。
- 浮窗条数不再是唯一高度来源：`SlotCount()` 按实际拖拽出的高度反推能放下几行，`UpdateCycleTimer` / `OnCycleTick` / `DrawRows` 统一用这个值，所以拉高就多显示几行、压低就少显示几行。
- 底图不透明度可降到 0%，此时不画底板也不画边框，只留文字；窗口本身始终无边框、始终是分层窗口（逐像素透明）。

## 构建和验证（Windows + .NET Framework 4.8）

```powershell
.\build-local.ps1          # 用系统自带 csc.exe 直接编译出 dist\QuantNative.exe
.\build.ps1                # 有 dotnet / msbuild 时走工程构建
.\run-tests.ps1            # 离线回归测试（46 项）
.\run-tests.ps1 -Network   # 附带网络接口测试（访问公开行情接口）
```

网络测试访问公开行情接口，对外部数据源的时延和可用性不作保证。测试数据位于 `work/tests/portable.dat` 隔离目录。独立试用 EXE 时可复制到新目录，并在同目录创建空 `portable.dat`。

离线界面预览（不需要显示器）：`run-preview.ps1` 会编译 `tests\UiPreview.cs` 并把主界面 / 设置页 / 浮窗 / 概览四张 PNG 输出到 `preview\`。

此候选 EXE 未签名。正式分发须通过 `verify-distribution.ps1` 的 Authenticode 签名和时间戳门槛；即便签名有效，也不能保证 Windows SmartScreen 对每台电脑都不提示。
